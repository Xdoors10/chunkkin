## 💡 Зачем

Сервер Minecraft сильнее всего проседает, когда игрок заходит в несгенерированную территорию: в одном тике надо и сгенерировать чанки, и отдать их клиенту. Chunkkin полностью убирает этот всплеск - он обходит чанки **по спирали от центра** (спавн готов первым), **настраиваемыми батчами** (TPS остаётся ровным), **сохраняет прогресс на диск** (рестарт ничего не теряет) и показывает всё вживую.

По сути Chunky, но нативно для ядра Pumpkin: Rust, WebAssembly, без JVM.

## ✨ Возможности

- 🌀 **Спиральный обход** - генерация стартует от центра и расширяется кольцами; спавн играбелен раньше дальних углов.
- 🟦 **Квадраты и прямоугольники** - один радиус даёт квадрат, два радиуса (X/Z) - прямоугольник, как у Chunky.
- ⚡ **Батчевая генерация** - настраиваемое число чанков за тик сервера держит TPS ровным, при этом загружая конвейер генерации полностью.
- 💾 **Перезапускаемые задачи** - прогресс чекпоинтится на диск; крэш или рестарт продолжают ровно с того же места.
- 🌍 **Локализация** - английский по умолчанию, русский одним полем конфига; переведено каждое сообщение, метка и справка.
- 📊 **Живая телеметрия** - прогресс-бар, скорость (чанков/с), ETA и прошедшее время в чате и консоли.
- ♻️ **Горячая перезагрузка конфига** - `/chunkkin reload` применяет язык и настройки движка без рестарта.
- 🔒 **Песочница** - исполняется в Wasmtime с доступом к файловой системе только в собственную папку данных.

## 📋 Команды

Основная команда: `/chunkkin` (алиас `/ck`). Требуемое право: `chunkkin:command` (по умолчанию разрешено).

### Настройка выбора (selection)

Выбор хранится в `config.json` и переживает перезапуски сервера - настройте один раз, запускайте когда угодно.

| Команда | Описание | Пример |
|---|---|---|
| `/ck world [мир]` | Целевой мир (без аргумента - ваш текущий мир) | `/ck world world_nether` |
| `/ck center [x z]` | Центр генерации в блоках (без аргумента - ваша позиция; поддерживается `~`) | `/ck center 1000 -2000` |
| `/ck radius <r> [rz]` | Радиус в блоках; два значения - прямоугольник | `/ck radius 5000` / `/ck radius 5000 2000` |
| `/ck selection` | Показать текущий выбор | `/ck selection` |

> [!TIP]
> По умолчанию: мир `world`, центр `0 0`, радиус `500` (квадрат 1000 × 1000 блоков).

### Управление задачей

| Команда | Описание | Пример |
|---|---|---|
| `/ck start` | Запуск генерации по текущему выбору | `/ck start` |
| `/ck pause` | Приостановка; прогресс сохраняется | `/ck pause` |
| `/ck continue` | Возобновление задачи | `/ck continue` |
| `/ck cancel` | Отмена и сброс задачи | `/ck cancel` |
| `/ck status` | Отчёт о прогрессе; повторный ввод включает/выключает прогресс в чате | `/ck status` |
| `/ck reload` | Перезагрузка `config.json` с диска без рестарта | `/ck reload` |
| `/ck help` | Справка в чате | `/ck help` |

## ⚙️ Конфигурация

Создаётся автоматически в `plugins/data/chunkkin/config.json`:

```json
{
  "language": "en",
  "selection": {
    "world": "world",
    "center_x": 0,
    "center_z": 0,
    "radius_x": 500,
    "radius_z": 500
  },
  "batch_size": 16,
  "log_interval_ticks": 100,
  "auto_save_interval_chunks": 1000,
  "auto_resume_on_startup": true,
  "console_log": true
}
```

| Параметр | По умолчанию | Описание |
|---|---|---|
| `language` | `"en"` | Язык сообщений: `"en"` или `"ru"`. Отсутствующие поля в старых конфигах получают значения по умолчанию. |
| `selection` | см. выше | Текущий выбор; меняется командами `/ck world` / `/ck center` / `/ck radius`. |
| `batch_size` | `16` | Чанков за тик сервера (20 тиков = 1 сек). Больше - быстрее, меньше - если проседает TPS. |
| `log_interval_ticks` | `100` | Период сообщений о прогрессе в тиках (100 тиков = 5 сек). |
| `auto_save_interval_chunks` | `1000` | Каждые N сгенерированных чанков мир сбрасывается на диск. |
| `auto_resume_on_startup` | `true` | Автоматически продолжать прерванную задачу при старте сервера. |
| `console_log` | `true` | Печатать однострочный прогресс в консоль сервера (прогресс в чате переключается через `/ck status`). |

## 🛠️ Сборка и установка

### Требования

- Rust 1.85+ (Edition 2024)
- Таргет WebAssembly WASI:

```bash
rustup target add wasm32-wasip2
```

### Сборка

```bash
cargo build --target wasm32-wasip2 --release
```

Артефакт: `target/wasm32-wasip2/release/chunkkin.wasm`.

> [!NOTE]
> `pumpkin-plugin-api` в `Cargo.toml` запинен на конкретный коммит Pumpkin. Если ваш сервер собран с другой версией - обновите `rev` (или переключитесь на `branch = "master"`), чтобы WIT-интерфейс совпал с сервером.

### Установка

1. Скопируйте `chunkkin.wasm` в папку `plugins/` сервера.
2. Убедитесь, что плагины включены в `pumpkin.toml`:
   ```toml
   [plugins]
   enabled = true
   ```
3. Запустите сервер (или сделайте hot-reload плагинов) и подтвердите права плагина при первом запуске.

## 🧭 Как это работает

```
        ┌─────────────┐     ┌──────────────────┐     ┌──────────────────┐
 /ck ──▶│  Selection  │────▶│  SpiralIterator  │────▶│  TaskManager     │
 start  │ (config.json│     │  (O(1) индекс →  │     │  батч за тик,    │
        │  хранится)  │     │   сдвиги колец)  │     │  save, resume)   │
        └─────────────┘     └──────────────────┘     └────────┬─────────┘
                                                         каждый тик
                                                  ┌───────────────▼────────┐
                                                  │  Pregenerator          │
                                                  │  запрос heightmap →    │
                                                  │  загрузка/генерация    │
                                                  │  чанка                 │
                                                  └────────────────────────┘
```

1. **Selection** - мир, центр и радиусы хранятся в `config.json` (в стиле Chunky).
2. **SpiralIterator** - превращает бегущий индекс в сдвиги колец арифметикой O(1); чанки обходятся от центра наружу.
3. **TaskManager** - обрабатывает `batch_size` координат за тик, чекпоинтит прогресс, автосохраняет мир и питает телеметрию.
4. **Pregenerator** - трогает heightmap каждого чанка, из-за чего система чанков Pumpkin его загружает или генерирует.
